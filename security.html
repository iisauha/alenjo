Privacy Security FAQ

Security

Last updated November 20, 2026

How each part of Alenjo is protected. Each section says what happens in plain terms; open How it works for the code.

Bank connections

  • You sign in to your bank inside Plaid’s window. Alenjo never sees that password.
  • Plaid gives Alenjo a one-time code. Only Alenjo’s server can trade it for a connection key, because the trade needs a secret that lives only on the server.
  • That key is read-only: it can fetch balances, transactions, card details and holdings. Alenjo doesn’t use Plaid’s money-movement products, so it can’t move money.
  • The key is encrypted in the database and never sent to your phone or browser.
How it works
// server: supabase/functions/plaid-link
const { access_token } = await plaid('/item/public_token/exchange', { public_token })
await db.rpc('insert_plaid_item', { p_user_id: user.id, p_access_token: access_token })
// inside the database: pgp_sym_encrypt(access_token, key from Supabase Vault)

Signing in

  • Email and password through Supabase Auth. Passwords are stored as bcrypt hashes, which can’t be turned back into the password.
  • Face ID uses a passkey. Your device creates a key pair; the private key stays in your iCloud Keychain and Alenjo stores only the public key.
  • Each Face ID sign-in signs a one-time challenge from the server. Nothing reusable is sent, so there’s nothing to steal and replay.
  • Sign-ups are closed. When they’re open, an invite code is checked on the server and the database rejects any new account without a fresh 15-minute ticket.
How it works
await sb.auth.signInWithPasskey()
// device: Face ID, then signs the server’s challenge with the private key
// server: checks the signature against the stored public key

While you’re using it

  • Every launch starts signed out on that device, unless the app is just locked.
  • After 1, 5 or 15 minutes away (your choice), the app locks. With Face ID it unlocks with Face ID; without it, you sign in again.
  • Deleting your account needs your password and typing DELETE.

The database

  • Every table has a row-level security rule, so the database only ever returns rows that belong to the signed-in user. This holds even if the app had a bug.
  • Account names, last 4 digits, balances, institution names and bank keys are encrypted with pgcrypto. The key is kept in Supabase Vault, not in the app or the code.
  • Photos and card images are in private storage buckets. Links expire after 7 days and only work for the owner’s folder.
  • All traffic uses HTTPS (TLS). Supabase also encrypts the disks the database runs on.
How it works

The rule on the transactions table. auth.uid() is the user ID inside your sign-in token:

create policy "Users see own transactions" on synced_transactions for select
  using ((select auth.uid()) = user_id);

Reading an encrypted balance, only possible inside locked-down database functions:

select pgp_sym_decrypt(balance_current_enc, private_get_encryption_key())
from accounts where user_id = auth.uid();

Server code

  • Bank work runs in Supabase Edge Functions: connecting, syncing, reconnecting, disconnecting, deleting your account, logo search, and checking invite codes.
  • Each one checks your sign-in token first and only touches your own rows.
  • Secrets (Plaid keys, the logo.dev search key) are stored as server environment variables, never in the app’s code.
How it works
const { data: { user } } = await supabase.auth.getUser()
if (!user) return new Response('Unauthorized', { status: 401 })

In the app

  • Text from banks and from you is escaped before it’s shown, so a store name can’t run as code.
  • The only scripts loaded are the app itself, the Supabase library (bundled with the app), Plaid’s connect window from cdn.plaid.com, and, only when you upload a card image, the image check from jsDelivr.
How it works
function esc(s) {
  return String(s).replace(/&/g, '&amp;').replace(/</g, '&lt;')
    .replace(/>/g, '&gt;').replace(/"/g, '&quot;').replace(/'/g, '&#39;')
}
